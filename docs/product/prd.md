# 产品需求文档 PRD（prd.md）

> 对应概要设计 2~7 章。产品总纲，所有产品/设计文档的依据。阶段：黑客松 MVP (v0.1)。

## 1. 项目背景
中国大陆城市数量庞大、地域差异明显、文化层次丰富。每座城市可能拥有独特的地标、历史人物、现代文化人物、影视符号、美食、方言、城市气质与地方记忆。

传统文旅产品以攻略、榜单、路线、点评为主，用户行为偏"查找信息"和"消费内容"，存在三个问题：
1. 探索过程缺少随机性与惊喜感。
2. 城市文化内容多为静态图文，互动性弱。
3. 用户浏览后缺少持续探索与收集反馈。

本项目结合「大富翁式随机移动 + AI 角色对话 + AI 图像生成 + 成就系统」，构建面向中国城市文化探索的互动产品。

## 2. 产品定位
本产品**不是**传统旅游攻略应用，**也不是**单纯的 AI 聊天产品。

> 定位：一个将中国城市文化、地图探索、游戏化随机漫游、AI 人物对话、AI 赛博打卡和成就收集结合的城市文化互动探索产品。

MVP 必须支持两种模式：
- **自由探索模式**：用户主动在地图上选择任意城市探索。
- **游戏互动模式**：用户从当前位置出发，通过随机方向 + 随机距离移动到下一城，形成大富翁式随机漫游。

两模式共享同一套城市探索能力：城市详情 / 地标 / 美食 / 人物 / 方言 / AI 对话 / 赛博打卡 / 成就解锁。

## 3. 产品目标

### 3.1 核心目标
构建以中国城市为核心内容载体的 AI 互动探索产品，让用户既能自由探索，也能通过随机机制获得游戏化漫游体验。

### 3.2 MVP 目标（9 条，需逐条验证）
1. 用户进入产品并选择探索模式。
2. 自由探索模式中主动选择城市。
3. 游戏互动模式中通过随机方向/距离前往目标城市。
4. 查看目标城市的地标、美食、人物、方言。
5. 与城市代表人物 AI 对话。
6. 上传照片生成城市地标背景的赛博游客照。
7. 完成城市打卡。
8. 基于打卡记录解锁成就/勋章。
9. 在 2C2G 单机环境稳定演示。

## 4. 设计原则（5 条）
| 原则 | 含义 |
|---|---|
| 双模式共存 | 同时支持自由探索(有明确目标)与游戏互动(无目标求惊喜) |
| 共享城市探索内核 | 两模式只在"如何到达城市"不同，到达后统一进城市详情页 |
| 轻后端、重体验 | 后端管状态/随机/AI编排/存储/成就；前端管地图/动画/交互 |
| AI 能力外部化 | 不本地部署大模型/生图模型，全调外部 API |
| 避免过度工程化 | 不引 Redis/Kafka/ES/向量库/网关/微服务，单体后端+MySQL |

## 5. 产品范围

### 5.1 MVP 必做（10 项）
模式选择 / 自由探索地图 / 游戏互动地图 / 城市详情页 / AI 人物对话 / 赛博打卡 / 打卡记录 / 成就系统 / 访问记录 / 单机部署。

### 5.2 MVP 暂不做（12 项及原因）
| 暂不做 | 原因 |
|---|---|
| 完整注册登录 | MVP 用匿名 user_id |
| 好友系统 | 非核心链路 |
| 排行榜 | 非核心链路 |
| 支付系统 | 不涉及商业化 |
| 后台管理系统 | 通过后台维护数据库 catalog；seed 仅作受控初始化/回填 |
| Redis 缓存 | 数据规模小，MySQL 足够 |
| 消息队列 | 无复杂异步任务 |
| 本地大模型 | 2C2G 资源不足 |
| 本地生图模型 | 2C2G 资源不足 |
| 全量中国城市 | 初期 12~20 精选城市 |
| 方言语音克隆 | 成本与合规风险高 |
| 真实多人实时互动 | 超出 MVP 目标 |

## 6. 用户角色
| 角色 | 说明 |
|---|---|
| 普通游客 Visitor | 主要用户。选模式、看内容、与人物对话、生成赛博照、打卡、解锁成就 |
| 演示管理员 Demo Admin | 通过后台管理维护城市/人物/地标/美食/成就；seed JSON 仅用于空库初始化或人工确认后的回填 |
